## 示例

**W01-2026: 分层架构**

**日期**：2026-03-20
**本周学习主题**：分层架构（Layered Architecture）

**这个概念是什么**：
把系统分成若干层，每层只依赖下层，不跨层调用。上层关心"做什么"，下层关心"怎么做"。

**在我当前项目里的映射**：
- 项目里有没有类似的结构？是
- 在哪里？产品有 UI 层（Qt Widgets）→ 业务逻辑层（xxxManager 系列）→ 数据访问层（DBHelper）。但业务逻辑层里有直接写 SQL 的代码，违反了分层原则。

**一个具体的改进想法**：
- 现状：XXXManager::loadData() 里直接调用 QSqlQuery::exec(SELECT ...)
- 改进后：改成调用 DBHelper::queryUsers(filter)，让业务逻辑层不知道 SQL
- 可能的代价：DBHelper 接口膨胀，灵活性降低（复杂的查询需要加很多方法）

**一个还没想明白的问题**：
如果某个查询性能很差，需要在业务层主动控制 SQL 怎么写——这时候打破分层合理吗？还是应该通过其他机制（如索引、缓存）解决性能问题，保持分层不变？
