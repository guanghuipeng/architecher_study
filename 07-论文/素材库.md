## 素材 1：组态软件的嵌入式脚本扩展（虚拟机/解释器风格）

- **项目**：工业组态软件——快速组态出监控界面，显示 CPU/GPU/温度/天气/内存等实时数据
- **你的角色**：（待补——架构设计者？核心模块负责人？）
- **背景/痛点**：组态编辑时要把控件**动态绑定**到数据库中的实时值，并写自定义逻辑（如"温度>70 显示报警"）；需求天天变，用户是组态工程师而非程序员，不能要求他们改 C++ 重编译
- **方案（架构风格）**：**虚拟机/解释器风格**——C++ 主程序（固定引擎）内嵌 Python 解释器，用户写的脚本是"程序数据"，被解释执行；改逻辑 = 改脚本，引擎一行不改
- **"做什么/怎么做"分离**：C++ 负责怎么做（渲染控件、连库、执行脚本）；用户脚本负责做什么（绑哪个值、什么条件报警）
- **关键技术**：C++ 嵌入 Python 解释器与执行环境（embedding）
- **踩过的坑 / 代价**：解释执行**性能慢**——但逻辑简单、触发低频、性能不敏感，可接受。真实印证"适合性能不敏感 + 需求多变"
- **效果**：用户可自定义绑定与报警逻辑，无需重编译发布
- **可对口的论文论题**：软件架构风格选择 / 系统设计
- **待补细节**：具体角色、脚本引擎选型理由（为什么 Python 而非 Lua/JS）、性能有无实测、上线效果数字
