# 评估方法对比表（SAAM / ATAM / CBAM）

> 来源：清华第2版《系统架构设计师教程》8.2 节。学日期 2026-09-13，与用户口述回炉共同填成。

## 一、三兄弟对比

| 方法（全称） | 递进定位 | 关键概念 / 技术 | 主要质量属性 / 代价 |
|---|---|---|---|
| SAAM（Scenarios-based Architecture Analysis Method，基于场景的架构分析方法） | 最早，判"架构**能不能**支撑" | 直接场景（不改就支持）vs 间接场景（要改才支持，间接多=架构别扭） | 主要看可修改性；质量属性分析弱 |
| ATAM（Architecture Tradeoff Analysis Method，架构权衡分析方法） | 补 SAAM 洞，聚焦质量属性，判"**好不好**" | 敏感点（单属性剧变）vs 权衡点（多属性此消彼长）+ 效用树分类排序 | 成本高（拉各方开会耗时）；吃场景质量 |
| CBAM（Cost Benefit Analysis Method，成本效益分析方法） | 叠在 ATAM 上，判"**值不值**" | 效用（0-100）、成本、ROI = 效用 ÷ 成本 | 项目干系人按 ROI 选架构策略 |

**一句话串起来**：能不能做（SAAM）→ 好不好（ATAM）→ 值不值（CBAM）。一脉相承，后一个补前一个的洞。

## 二、补充细节（备查）

- **ATAM 四阶段**：演示 → 调查分析（找敏感点/权衡点 + 风险）→ 测试（深挖高优先级场景）→ 报告。
- **CBAM 八步骤**（核心逻辑）：列架构策略 → 定场景权值 → 定效用表 → 内插算效用 → 算总收益 → 估成本 → 算 ROI → 按 ROI 排序选策略。
- **敏感点 vs 权衡点**：敏感点 = 某决策影响**单一**属性、一动它那个属性剧变（如连接池大小→性能）；权衡点 = 某决策影响**多个**属性且此消彼长、一动它 A↑B↓（如内联+全局变量→性能↑可修改性↓）。
